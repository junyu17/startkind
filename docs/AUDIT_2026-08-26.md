# StartKind Audit — 2026-08-26

**Scope:** the full working tree (app, share extension, widget extension, watchOS app, tests, docs).
**Method:** read every changed file plus the previously unreviewed ones, then static sweeps for
localization parity, dead code, unsafe unwraps, range traps, view-body publishes, and
identifier collisions. Every finding below was confirmed in source before being fixed.

## Baseline (before fixes)

| Check | Result |
|---|---|
| Debug simulator build | Passed, 0 warnings |
| Unit suite | 132 executed, 3 skipped, 0 failures |
| UI suite | 26 executed, 0 failures (385 s) |

A green suite is why this audit reads source rather than trusting the tests: every defect
below was invisible to the existing suite.

## Findings fixed

### Crash and correctness

1. **Live Activity and watchOS countdown trapped once a timer expired.**
   `Text(timerInterval: Date.now...endsAt)` builds a `ClosedRange`, which traps when the
   upper bound is in the past. Any re-render after the planned end (backgrounding and
   returning, a Live Activity refresh) killed the widget extension. Fixed with a clamped
   `min(now, endsAt)...endsAt` helper in both targets.
2. **`FlowLayout` reported a width of `.infinity`** on an unspecified proposal, used
   different row-break rules in `sizeThatFits` vs `placeSubviews`, and took each row's
   height from only its *first* chip — so a taller wrapped chip clipped. Rewritten around
   one shared row calculation.
3. **StoreKit listener leaked on every paywall presentation.** `EntitlementService.load()`
   is called from `PaywallView.task`, and each call spawned another `Transaction.updates`
   listener, so transactions were finished and entitlements refreshed N times. Guarded.
4. **A corrupt or incompatible SwiftData store made the app permanently unlaunchable.**
   `AppEnvironment.init` called `fatalError` on any container failure. Now the unreadable
   store is moved aside once and a clean one is opened; an in-memory store is the last
   resort so the app still launches.
5. **"Delete account & data" silently reverted for signed-in users.** It wiped only local
   SwiftData rows; the next `syncAll` pulled every row straight back from Supabase. It now
   deletes the user's remote rows (participants before rooms), signs out, then wipes local.
   Confirmation copy updated in both languages.
6. **`RecoverView` could present an empty, contentless timer sheet** via
   `fetchNextStep(id: session.nextStepId ?? UUID())`. Now binds the optional properly.

### Localization (zh-Hans is a shipping language)

7. **No `InfoPlist.strings`** — every permission prompt (microphone, speech, camera, photo
   library) and all four Home Screen quick-action titles were English-only. Added for
   `en` and `zh-Hans`, verified present in the built bundle.
8. **The watchOS app was 100% hardcoded English.** Now reads its own
   `Localizable.strings` in both languages.
9. **The share extension's "Opening StartKind…" was hardcoded English.** Localized.
10. **`UsageError`, `SpeechError`, `AuthError` returned hardcoded English** from
    `errorDescription`, and those strings reach the UI. Routed through `L()` with new keys.
11. **Three call sites bypassed the in-app language picker** by using SwiftUI's
    `LocalizedStringKey` / `NSLocalizedString`, which read the *system* bundle:
    `AuthView`'s keyboard Done button, `TaskCategory.displayName`, and
    `EntitlementState.displayName` (the visible subscription status). All now use `L()`.
12. **125 sites used ASCII `,` `?` `:` inside Simplified Chinese copy** across the string
    table and nine domain files. Converted to fullwidth `，？：`.
13. **`recover.related` concatenated a hardcoded `": "`**, producing `备注: x` in Chinese.
    Converted to a proper format string.

### Dead code and duplication

14. `AppEnvironment.pendingStuckRestart` — nothing ever set it to `true` after the stuck
    button moved into `StartView`; the flag and its `onChange` handler were dead.
15. `AdminQuickReaderView.recognizeText(from data: Data,…)` — no callers after the
    `PhotosPicker` → `UIImagePickerController` switch.
16. `TimerView`'s `pendingOutcome == .abandoned` branch — `.abandoned` is never assigned,
    so `blocker.title.skip` was unreachable.
17. `PaywallView.planButton` tested `isAnnual` and `id == SubscriptionProductID.annual` as
    two separate `if` blocks; four sites re-derived the same condition.
18. `PaywallView` passed an already-localized string to `PrimaryButton(_ key:)`, which
    localizes again. Switched to the existing `verbatim:` initializer.
19. `PaywallView.task` reassigned `selected` to the value it already defaults to.
20. `StartView.shrink(_:)` compared `proposal.shrinkLevel == step.shrinkLevel` after
    `updateNextStep` had already written that level onto `step` — always true.
21. `sk_has_started` was written in two places and never read.
22. `kindStartButton` applied the same accessibility identifier twice.
23. Seven `paywall.feature.*` keys orphaned by the paywall redesign, removed from both tables.

### Security and robustness

24. **Supabase access and refresh tokens were persisted in `UserDefaults`** — a plain plist
    in the app container, included in unencrypted backups. Moved to the Keychain
    (`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`) with a one-time migration that
    deletes the plaintext copy.
25. Force-unwraps removed from `RecoveryCapsuleModel.blockerDraft` and from the
    `table[category] ?? table[.other]!` lookups in `NextStepEngine` and `TaskShrinker`
    (the `.other` entry is now a named constant, so the compiler guarantees it).
26. Force-unwrapped `UserDefaults(suiteName:)!` in `StartKindApp.init` replaced with a fallback.

### Product surface

27. **The in-app data export could not be copied or shared** — a data-portability feature
    that only rendered unselectable text. Added text selection and a `ShareLink`.
28. **`TimerView`'s "+5 minutes" and pause did not reach the Live Activity**, so the Lock
    Screen countdown desynced from the in-app timer. `ContentState` gained
    `pausedSecondsRemaining`; the widget shows a frozen time while paused.
29. The support email was hardcoded in two views while `settings.contactEmail` existed.
30. `openMoreWays` in the UI tests carried a dead Chinese-label branch (the suite forces
    English), an unreliable `isSelected` check, and a double-tap retry that could
    re-collapse the section. Simplified.
31. Docs claimed the Stuck button was "available from the tab shell" / "from any tab";
    it now lives in the Start first viewport. Four doc lines corrected.

## Round 2 — backend and cross-tier findings

The first pass covered the app. This pass covered the Supabase Edge Functions, the RLS
policies, and the Free/Plus boundary across the client/server seam.

32. **`verify_receipt` never checked whether the entitlement write succeeded.** A failed
    upsert still returned 200, so the client believed Plus had synced while the
    server-side source of truth that gates `one_next_step` / `admin_task_reader` stayed
    stale. Now returns `entitlement_write_failed`.
33. **Free trials were reported as `plus_active`.** Apple sets `is_trial_period` for a free
    trial; `is_in_intro_offer_period` is for *paid* introductory offers. Both are checked now.
34. **`verify_receipt` did not verify the receipt's `bundle_id`.** The shared secret already
    rejects other apps' receipts, but Apple documents the bundle check — added as
    defense in depth.
35. **`one_next_step` burned a free step on server failures.** The `ai_usage` row was
    inserted before the `OPENAI_API_KEY` check and before the AI call, so a 503 or an AI
    error still cost the user one of their five. Usage is now recorded only after the call
    succeeds — the same defect class as the friend co-start quota bug in round 1.
36. **Neither AI function capped input length**, so one large paste went straight to the
    paid model. Both clamp to 4000 characters.
37. **Signed-in Free users lost their documented one-per-day Admin Quick Start.** The
    server returns `plus_required` for any non-Plus caller, and the client translated that
    into `UsageError.adminLimitReached` — a paywall instead of the allowance. Free users
    now fall back to the local reader, and the paywall is raised by
    `canUseAdminQuickStart` once the allowance is actually spent. This path is reachable
    for anyone who signed up without subscribing, and for guests who joined a friend's
    co-start room via anonymous sign-in.
38. **`delete_account` Edge Function added** (see Open items 1). The account to delete is
    taken only from the verified JWT — nothing is read from the request body — and the
    delete is an explicit hard delete, because a soft delete would not cascade the user's
    rows. The app calls it first and falls back to per-table deletes if it is unreachable.
39. `corsHeaders` was imported but unused in three functions; `verify_receipt` also hand-rolled
    its OPTIONS response, omitting `Access-Control-Allow-Headers`. Both tidied.
42. **`PersonalVaultStore` fell back to a hardcoded English "Saved start"** when a vault
    entry had a blank title — user-visible text in a bilingual app. Now `vault.defaultTitle`.

### Test reliability

40. **My own round-1 simplification of `openMoreWays` was wrong.** Removing the retry made
    `testCategorySelectionShowsFeedback` fail: the DisclosureGroup does not always expand
    on the first tap. It now retries up to three times, re-checking before each tap so a
    slow expansion is never toggled shut — which the original double-tap could do.
41. **`testKindStartAdminReaderParsesBillText` raced the sheet animation**, typing into
    `admin.input` before it held keyboard focus. A `focusAndType` helper waits for the
    keyboard first. No assertion was weakened.

**A note on the noisy runs.** Several verification runs during this audit failed with
9-14 failures, bizarre element bounds (a text field reported as 89x7pt), "test runner hung
before establishing connection", and partial suites. None of it was the code: a second
`xcodebuild test` for another project was running against the same simulator and
terminating StartKind mid-test. The app itself renders correctly (verified with a direct
screenshot), and the suite is green on a dedicated device. Two lessons worth keeping:
run this suite on its own simulator when other work is active, and never edit the tree
while a verification run is in flight.

## Round 3 — pre-submission sweep

Run after the CloudKit/backend migration and the device-testing fixes, with the
Supabase directory removed.

43. **Data export was unreachable.** Settings stacked two `.sheet(isPresented:)`
    modifiers on one view; tapping Export produced no usable sheet, so the
    in-app data export — a privacy-facing feature — could not be opened at all.
    Both sheets are now one `.sheet(item:)` carrying the exported text with it,
    which also removes the empty-sheet failure mode.
44. **`SFSpeechRecognizer` was built before authorization.** An instance created
    while speech access is still `.notDetermined` keeps reporting
    `isAvailable == false` after the grant, so the first tap after authorising
    threw `.notAvailable` and the error rendered below the fold — it looked like
    voice capture simply did nothing. Built after authorisation now, with an
    en-US fallback when the device locale has no recognizer.
45. **Entitlement was asserted to the backend exactly once, at purchase.** A
    single failed attempt left a paying user on Free limits server-side forever
    while the app still showed Plus. Re-asserted on every launch.
46. The header card's arrow read as a control and did nothing; removed.
47. Co-start reported the same message for every failure, including an
    unreachable backend. Network failures now say so.
48. The whole `supabase/` directory (22 files) and every stale reference to it
    in `AGENTS.md`, the brief, and the architecture, data-model, roadmap and
    testing docs. Dated historical reports keep their Supabase mentions as
    record.
49. 44 localization keys left unreferenced — 17 orphaned by removing the account
    system, the rest older. Removed from both tables.

### Coverage added

`ScreenWalkthroughTests` opens every screen, panel and sheet the app can reach
and asserts it renders: the Start first viewport, all ten More-ways panels,
energy and friction chips, templates and vault sheets, all four tabs, every
Settings section, privacy, export and the paywall. `PlusEntitlementTests`
asserts each Free/Plus gate on both sides, plus that an expired subscription
returns to Free limits.

### Known fragility, verified safe

Four sheets build their content behind `if let` on optional state
(`StartView` ×3, `AdminQuickReaderView` ×1). That is the shape that made the
export bug invisible: when the optional is nil the sheet presents empty rather
than not at all. Every call site was checked and sets the optional before the
presentation flag, and the UI suite exercises all four paths, so they are
correct today — but the pattern is worth replacing with `sheet(item:)` when
those views are next touched.

## Checked and deliberately left alone

- **`deleteAllData()` does not reset the free usage quota.** Resetting it would let anyone
  clear their daily limit by tapping "delete data". Intentional.
- **The bad-day path in `generateNextStep` does not consume a free step.** Consistent with
  the product's no-punishment rule.
- **Dynamic Type.** Every body, caption, headline and title in the app uses semantic fonts
  and scales correctly. Sixteen call sites use a fixed `.font(.system(size:))`: eleven are
  SF Symbols inside fixed-size frames (scaling them would break those layouts), and the
  remaining four are display numerals already set very large — the timer countdowns
  (`TimerView.swift:60` at 72pt, `CoStartView.swift:303` at 64pt) and the room codes
  (`CoStartView.swift:219` and `:360` at 34-36pt). Left alone because changing them alters
  the approved visual design; worth revisiting with `@ScaledMetric` if you want the
  countdown to grow at accessibility sizes.
- **`AppEnvironment.usageState` reads the stored counter without forcing a reset.** Making
  it refresh would publish during a view update; `refreshUsage()` already runs on
  `scenePhase == .active`, which covers the real cases.

## Open items

1. **`delete_account` is written but cannot be deployed: the Supabase project is PAUSED.**
   `supabase functions deploy` fails with *"Cannot retrieve service for project
   yekmovuqakbekfmgtuvj with current status 'INACTIVE'"*, and the REST/auth endpoints do
   not respond at all. A free-tier project pauses after 7 days idle, so **the backend
   cannot support a shipped App Store app as configured** — restoring it only restarts the
   same 7-day clock. This must be resolved before submission (Pro plan, or self-hosting).
   Unpausing is dashboard-only; the CLI has no restore command.
2. **`SupabaseClient` is `@unchecked Sendable` with mutable token state.** Its non-isolated
   async methods can mutate `accessToken`/`refreshToken` off the main actor concurrently.
   `SWIFT_STRICT_CONCURRENCY` is `minimal`, so the compiler does not flag it. Making the
   class `@MainActor` is the clean fix but touches several call sites — worth doing
   deliberately, not as part of a release-eve sweep.
3. **27 unreferenced localization keys remain** (`onboard.*`, `capture.fallback`,
   `timer.outcome.completed/partial/paused`, `nextstep.title/why/stop/estimated/tryVersion`,
   `common.ok/continue/loading/gotIt`, `timer.after*`, `timer.remaining/step`,
   `paywall.subtitle/trial`, `recover.resume`, `settings.subscription.manage`,
   `start.voice.button`, `usage.stepsReset`). All predate this batch and are provably
   unreachable, but they are translated copy — deleting is a product call.
4. **The Stuck button is no longer global.** It was a floating button over the tab bar and
   is now in the Start first viewport only. Docs were corrected to match the code; if the
   always-available escape hatch was the intent, the button should return to `RootView`.
5. **Six-digit room codes are generated without a collision check.** Two users can draw the
   same code; disambiguation has to happen server-side in `join_co_start_by_code`.
6. **`TimerView`'s "Make it smaller" and "I got interrupted" do the same thing.** Both open
   the blocker picker and emit `.paused`. That is defensible — the product shrinks paused
   work either way — but "Make it smaller" already states its own reason, so the extra
   picker step is a decision the user did not need to make. Sending it straight through as
   `.tooBig` would remove a tap; left unchanged because it is a UX call, not a bug.
7. **App Intents phrases and titles are English-only.** `Metadata.appintents` is generated
   correctly, but the `AppShortcut` phrases and `LocalizedStringResource` titles have no
   Chinese variants, so Siri invocation works only in English.
